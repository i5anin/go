# Go Taskbox

Небольшой учебный HTTP-сервис задач на Go. Только стандартная библиотека, без фреймворков и внешних зависимостей.

## Что здесь показано

- REST API: создание, список, отметка выполнения, удаление.
- Структуры, методы, обработка ошибок, JSON и маршрутизация `net/http`.
- Потокобезопасность через `sync.Mutex` и конкурентные тесты.
- Хранение событий в JSONL: запись и `Sync` до изменения памяти, восстановление после перезапуска.
- Ограничение тела запроса, проверка полей, тайм-ауты и завершение по Ctrl+C.

## Запуск

Нужен Go 1.24 или новее. Из папки проекта:

```powershell
go test ./...
go vet ./...
go run .
```

По умолчанию сервис доступен только на этом ПК: http://127.0.0.1:8080/health

Данные сохраняются в `tasks.jsonl` в текущей папке и исключены из Git.

```powershell
go run . -addr 127.0.0.1:8081 -data tasks.jsonl
```

## Попробовать в PowerShell

```powershell
$base = 'http://127.0.0.1:8080'
$task = Invoke-RestMethod "$base/tasks" -Method Post -ContentType 'application/json' -Body '{"title":"Learn Go"}'
Invoke-RestMethod "$base/tasks"
Invoke-RestMethod "$base/tasks/$($task.id)" -Method Patch -ContentType 'application/json' -Body '{"done":true}'
Invoke-RestMethod "$base/tasks/$($task.id)" -Method Delete
```

## API

| Метод | URL | Тело | Ответ |
|---|---|---|---|
| GET | `/health` | — | 200: liveness |
| GET | `/tasks` | — | 200: массив задач |
| POST | `/tasks` | `{"title":"Learn Go"}` | 201: задача |
| PATCH | `/tasks/{id}` | `{"done":true}` | 200: задача |
| DELETE | `/tasks/{id}` | — | 204 |

Неверные данные: 400. Неизвестная задача: 404. Ошибка хранения: 500, подробность только в журнале сервера. Название: 1–200 Unicode-символов после обрезки пробелов. Тело запроса: максимум 4 КБ, неизвестные JSON-поля запрещены.

## Проверки

```sh
go test -race -cover ./...
go vet ./...
go build -o taskbox .
```

На Windows для `-race` нужен поддерживаемый C toolchain; обычные `go test ./...` не требуют его.

## Как читать код

1. `main.go`: HTTP-обработчики, валидация и запуск.
2. `store.go`: модель задачи и журнал событий.
3. `main_test.go`: API, сохранение после перезапуска, параллельные записи, повреждение файла и ошибка записи.

## Границы учебного примера

Это не production SaaS: нет аутентификации, TLS, лимитов числа задач и ротации журнала. Не выставляйте сервис в интернет. `/health` проверяет жизнь процесса, а не исправность диска.

Запускайте **только один процесс на один файл**. Блокировка защищает goroutine внутри процесса, не несколько процессов. Журнал растёт при каждом изменении; удаление задачи не удаляет её старые данные из журнала. Храните резервные копии остановленного сервиса в приватном месте. Секреты и личные данные для демонстрации не нужны.

Повреждённый или незавершённый журнал не исправляется автоматически: запуск остановится без изменения исходного файла. Восстановите проверенную резервную копию. `Sync` снижает риск потери данных, но не заменяет резервное копирование и не гарантирует сохранность при отказе оборудования.
